## VLM-NAV 架构评价（修正版，整合 Codex 反馈）

本版本整合了 Codex 对初稿的纠正，区分了"仍然成立的结构性问题"和"已部分过时的评价"。

---

### 一、架构优势

**1. VLM + 经典机器人的混合设计思路正确**

项目采用 **"VLM做高层推理 + 经典方法做底层安全"** 的分层架构，而不是端到端学习。在当前VLM能力边界尚不明确的情况下是务实的选择：

- VLM 只负责从候选中选一个（选择题），而不是直接输出连续控制信号（填空题），大幅降低了对 VLM 精度的要求
- Occupancy Grid + A* 做安全过滤，VLM 永远看不到不可达的选项，从根本上避免了"VLM 建议撞墙"的问题
- DepthSafetyMonitor 作为最后一道防线，即使 VLM + 几何规划都出错也能兜底

**2. 决策链路比表面看起来更深**

step() 方法实现了 10 级优先级链路，不是简单的"5 选 1"：
1. ROUTE_COMPLETE → STOP
2. RECOVERY 续执行
3. RECOVERY 启动（STALLED/SPINNING）
4. ACTIVE_GOAL 续执行（含里程计完成检查）
5. REPLAN_COOLDOWN → STOP
6. 候选预测 + 占据栅格过滤
7. **SEMANTIC_LOCAL_PLANNER** → A*子目标，完全绕过VLM
8. VLM决策（choose_candidate）
9. LLM_BLOCKED 处理
10. Reacquire Guard 覆盖

其中第 7 步是关键——一旦有 grounded landmark anchor，主链直接切到几何规划，不再走 VLM。这意味着系统并非始终依赖 VLM 做每一步决策。

**3. 容错设计层次丰富**

```
VLM决策 → ReacquireGuard覆盖 → DepthSafety覆盖 → StuckDetector恢复
```

四层容错在工程上很扎实，尤其 Reacquire Guard 防止"看到目标后丢失→原地打转"的死循环。

**4. SAM 已集成且有 CPU 容错**

SAM 已接入主 grounding pipeline（target_grounding.py:526），CUDA OOM 时自动降级到 CPU 重试（sam_segmenter.py:66-84）。SAM 完全失败时降级到 bbox 深度统计。视觉定位链路是完整的。

**5. 异步视觉定位 + 观测复用**

TargetGrounder 用 ThreadPoolExecutor 异步运行 GroundingDINO/SAM，不阻塞主循环。两次定位之间复用上次结果但标记为 transient，不会当作新证据。

---

### 二、仍然成立的结构性问题

**1. [最关键] 指令理解——纯正则解析，几乎为零的语义能力**

instruction_manager.py 的指令解析完全靠正则：
- 地标词汇表仅 11 个词（wheelchair, stairs, door, chair, bed, desk, table, elevator, hallway, corridor）
- 子句分割靠 "then"/"next" 等连接词
- 没有共指消解、没有语义角色标注、没有依存分析

**"go past the door and turn left at the stairs"** 这种简单指令都无法正确解析出"先经过门，在楼梯处左转"的时序关系。指令解析的输出直接影响 LandmarkTracker 的初始化和路线推进——如果 landmarks 列表为空，整个追踪链就断了。

这是当前工程最大的上层短板，不是控制器，而是"指令根本没有被可靠地结构化"。

**2. 没有全局地图——只有局部占据栅格**

occupancy_grid.py 维护的是一个 24m×24m 的 odom 坐标系下的局部栅格：
- 机器人走远后，旧区域会被 decay 掉（衰减率 0.990）
- 没有回环检测、没有全局 SLAM、没有拓扑图
- 无法实现"回到之前经过的路口"这种全局规划
- 当前有 landmark anchor 和记忆，但还不是拓扑图/全局语义图

长程导航下会退化成"看见就走、看不见就忘"。

**3. Route Consistency 检查只记日志，不触发重规划**

_log_route_consistency_if_needed()（vln_policy.py:1260-1290）检测到路线矛盾时，只写 warning 日志，不触发任何纠正动作。没有下游状态修改，没有返回值，没有标志位设置。纯粹是观测/诊断性质的。

**4. 地标确认机制过于保守，可能导致"永远到不了"**

LandmarkTracker 的到达检测（landmark_tracker.py:264-309）需要 arrival_confirmations 次**连续**确认，不是滑动窗口：
- 满足条件时 reached_count + 1
- **不满足时 reached_count 直接清零**（line 306）
- transient 观测不计入
- visible_count 也会被清零（line 138-141），形成"双重连续"要求

如果 GroundingDINO 偶尔漏检，机器人可能在地标面前反复"看到→丢失→重置计数"，永远无法确认到达。

### 三、已部分过时的评价（需修正）

**1. ~~"系统就是 VLM 从 5 个固定候选里选一个"~~ → 不完全对**

搜索阶段确实还是 5 槽位候选 [-75°, -35°, 0°, +35°, +75°]，但这只是决策链的第 6-8 步。一旦有 grounded landmark anchor，主链会切到 SEMANTIC_LOCAL_PLANNER（vln_policy.py:317-361），用 A* 路径规划直接生成子目标，完全绕过 VLM。

所以候选槽位的局限性主要影响"搜索阶段"（目标还未被定位时），而非整个导航过程。但在搜索阶段，5 个固定槽位的精度问题仍然成立。

**2. ~~"SAM 没真正接入"~~ → 已接入**

SAM 在 target_grounding.py:526 被调用，有 CUDA→CPU 自动降级，有完全失败时的 bbox 深度 fallback。链路完整。

**3. ~~"VLM 同步调用是唯一瓶颈"~~ → 真正更痛的瓶颈在别处**

VLM API 延迟确实存在（1-3秒），但当前真正更痛的瓶颈是：
- 局部地图几何还不稳定（占据栅格的 decay 和漂移）
- 没有全局回溯记忆
- 指令结构化太弱

DepthSafetyMonitor 可以在 VLM 延迟期间兜底做 STOP/BACKWARD，紧急避障不受 VLM 延迟影响。VLM 延迟更多影响的是"决策频率"而非"安全性"。

### 四、与主流 VLN 方法的系统对比

| 维度 | VLM-NAV | Seq2Seq/Attention (2018) | VLN-BERT/HAMT (2021) | MapNav (2023) | 用 GPT-4V 做 VLN (2024) |
|------|---------|------------------------|---------------------|--------------|----------------------|
| **指令理解** | 正则 + VLM隐式处理 | LSTM encoder | BERT cross-attention | Transformer | GPT-4V 直接理解 |
| **视觉表示** | RGB-D + LiDAR + 占据栅格 | Image features (ResNet) | Panoramic features | 拓扑图节点 | 单帧 RGB |
| **空间记忆** | 局部 24m 栅格 + landmark anchor，无全局拓扑 | 无 | 历史注意力窗口 | 增量拓扑地图 | 无/对话历史 |
| **动作空间** | 搜索期5槽位 + 语义规划期A*子目标 | Forward/Left/Right/Stop | 连续 heading | 拓扑节点跳转 | VLM输出文本动作 |
| **泛化性** | 零样本（VLM驱动） | 需要训练 | 需要预训练+微调 | 需要预训练 | 零样本 |
| **鲁棒性** | 四层容错 + SAM降级，工程扎实 | 无安全机制 | 无 | 有回溯机制 | 无 |
| **部署成本** | VLM API 依赖 | 纯本地 | 纯本地 | 纯本地 | VLM API 依赖 |
| **长程导航** | 差（无全局拓扑） | 差 | 中等 | 好（拓扑图） | 差 |

### 五、改进建议（按优先级排序，采纳 Codex 的排序意见）

**P0 - 用 VLM 做指令预处理** [最重要]
在导航开始前，调用一次 VLM 将自然语言指令解析为结构化的路线表示：
```json
{
  "landmarks": ["door", "stairs", "elevator"],
  "directions": ["pass", "turn_left_at", "arrive"],
  "temporal_order": [0, 1, 2],
  "spatial_relations": [{"from": "door", "to": "stairs", "relation": "then"}]
}
```
替代硬编码的 11 词正则。成本只是一次额外 API 调用，收益是能处理任意自然语言指令。

**P1 - 引入拓扑/语义记忆层**
在 OccupancyGrid 之上加一层拓扑图，节点是路口/关键位置，边是可达关系。机器人每到一个新区域就建节点，支持回溯和全局重规划。当前的 landmark anchor 是空间记忆的雏形，但缺少拓扑连接关系。

**P2 - Route Contradiction 触发纠偏**
_log_route_consistency_if_needed() 已经能检测矛盾，只差触发动作。建议：
- 矛盾时触发 VLM 重新评估当前目标
- 或设置标志位让 SEMANTIC_LOCAL_PLANNER 重新规划路径
- 极端情况请求人类确认

**P3 - 到达确认改为滑动窗口**
将连续确认改为滑动窗口确认（比如最近 5 次中 3 次确认即可），避免单次漏检导致计数器重置。具体改动：
- landmark_tracker.py:264-309 的 _update_reach_state() 中，将 reached_count 清零改为滑动窗口数组
- _maybe_advance_landmark() 中的 _arrival_confirmation_count 同理

**P4 - 自适应候选航点** [优先级最低，因为 SEMANTIC_LOCAL_PLANNER 已覆盖大部分场景]
搜索阶段的 5 个固定槽位可以优化：
- 根据占据栅格的局部拓扑动态调整候选数量和方向
- 窄走廊时在前方密集采样，宽阔区域时增加候选覆盖面
- 但这个优先级最低，因为一旦目标被定位，SEMANTIC_LOCAL_PLANNER 会接管

---

### 六、总结

如果只说一句最关键的：P0 和 P1 是最重要的，尤其是 P0。当前工程最大的上层短板不是控制器，而是"指令根本没有被可靠地结构化"。工程鲁棒性（容错、降级、异步）做得很好，核心差距在指令理解的语义深度和全局空间记忆。
