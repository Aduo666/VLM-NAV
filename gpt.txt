这个计划方向是对的，可以做。但有几处需要先修正，否则 mimo 实现后还会出现“误完成”或“永远不完成”。

**必须修正的点**
1. `qwen_fallback_confirm_allowed` 不能只放在 `LandmarkTrackerConfig`。  
因为 `can_confirm` 是在 `target_grounding.py` 里生成 `TargetObservation` 时决定的，所以这个字段必须传进 `TargetGroundingConfig`，否则 `target_grounding.py` 读不到。

2. `vln_policy.py` 不要重复判断一堆阈值。  
更稳的做法是让 `LandmarkTracker` 输出统一结论：`state.can_complete`。  
`vln_policy.py` 只看：
```python
tracker_state.can_complete
tracker_state.evidence_level == "confirmed"
tracker_state.anchor_distance_m <= turn_at_complete_max_distance_m
```
否则阈值会在 tracker / map / policy 三处重复，后面很难调。

3. `state.confidence = observation.confidence if visible else state.confidence` 有风险。  
如果已经 confirmed，后面来一个低置信 potential，会把 confirmed confidence 降低。  
建议改成两个字段：
```python
potential_confidence
confirmed_confidence
```
如果不想新增字段，那就规定 `state.confidence` 只代表 confirmed confidence，potential 用 `potential_confidence`。

4. confirmed 累计必须只统计 fresh 当前帧观测。  
条件里要加：
```python
observation.is_current_frame
"reused" not in observation.source
observation.reason == "ok"
```
否则旧帧结果或复用结果会累计成 confirmed。

5. `LandmarkMap` 不要自己重新判断所有阈值。  
建议只接受：
```python
state.can_complete == True
state.evidence_level == "confirmed"
state.estimated_world_xy is not None
```
然后把 `confirmed_observation_count` 和 `evidence_level` 存进去。这样 map 不会和 tracker 判断不一致。

6. `turn_at_complete_max_distance_m: 3.0` 可以保留，但不是主要保护。  
之前误完成时距离是 `2.03m`，如果只加距离上限依然会完成。真正关键是：Qwen fallback 不能 confirm，以及必须多帧 confirmed。

7. 这个计划还没有真正处理“视野里出现两个 landmark”。  
当前系统一次只 grounding 当前目标，所以不会同时检测多个 landmark。短期可以接受，因为 route index 限制当前目标；长期如果要处理多 landmark，需要新增 multi-target grounding。现在先别做，避免扩大范围。

**我建议的修正版**
- `target_grounding.py` 负责输出 `potential / confirmed_candidate` 和 `can_confirm`。
- `LandmarkTracker` 负责把 confirmed_candidate 累计成真正 `confirmed`。
- `LandmarkMap` 只写入 `state.can_complete=True` 的 confirmed landmark。
- `vln_policy` 只允许 `can_complete=True` 的 landmark 推进 route。
- SAM 保留，但只做 mask/depth，不参与语义确认。

**关于 GroundingSAM**
先不要删。当前误识别主要来自 Qwen bbox 或 grounding 语义本身，SAM 只是接着这个 bbox 做分割和深度。正确处理是：`qwen_vl_bbox + sam_vit_h` 仍然只能是 `potential`，不能触发 route complete。

**可以让 mimo 开始改，但要加这条硬约束**
所有能触发 `[Landmark] reached=... route=complete` 的路径，必须经过：
```python
tracker_state.can_complete == True
```

如果日志里没有出现：
```text
evidence=confirmed
can_complete=1
confirmed_obs>=3
```
就绝不能出现：
```text
route_complete=1
```
