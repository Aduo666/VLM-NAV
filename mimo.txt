一、改动汇总
============

1. 核心：证据等级系统 (potential vs confirmed)
---------------------------------------------

目标：防止低置信度/误检目标触发 route_complete，只允许经过多帧稳定确认的目标完成导航。

新增 evidence_level 字段贯穿整个管线：
  - "none": 未检测到
  - "potential": 低置信度/Qwen来源/无深度 → 可见但不能触发完成
  - "confirmed_candidate": DINO来源且有深度，但尚未累积足够帧数
  - "confirmed": 已通过 N 帧一致性验证 → 可以触发到达判定和 route_complete

can_complete 门控：只有 confirmed + estimated_world_xy != None + confirmed_observation_count >= N 时才为 True。

3. SAM 禁用
-----------

问题：SAM vit_h 模型约 2.4GB，加载到 GPU 导致 OOM → 回退 CPU → 每次调用 10-20秒，
阻塞整个控制循环，车几乎不动。

解决：configs/default.yaml 设置 sam_enabled: false，完全跳过 SAM。
GroundingDINO 独立完成检测，深度估算回退到 bbox-based approach。


4. depth_invalid 透传
---------------------

问题：GroundingDINO 检测到目标但深度验证（valid_ratio < 0.12）拒绝所有观测。

解决：深度验证失败不再返回空观测，而是返回：
  visible=True, depth_m=None, evidence_level="potential", reason="depth_invalid"
机器人至少知道目标在视野中。tracker 的 fresh_visible 也更新为接受 reason="depth_invalid"。

二、问题分析
============

问题1：为什么直走的好好的会右转，ground在左边？
--------------------------------------------

### 可能原因分析

(a) VLM决策覆盖grounding信号

  决策流程：
  1. GroundingDINO 检测目标 → 得到 bbox center_uv → 计算 bearing_rad
  2. VLM reasoner 接收带标注的图像 + 候选列表
  3. VLM 选择一个 candidate → 得到 selected_action
  4. 如果 VLM 返回 selected_action="TURN_RIGHT"，即使 grounding 显示目标在左边，
     最终执行的仍然是 TURN_RIGHT

  代码位置：vln_policy.py L568-579
  action_name 优先级：route_corrected > decision.selected_action > _candidate_to_primitive_action()
  VLM 的 selected_action 会直接覆盖 candidate 自身的 heading 推断。

  VLM 看到的图像可能与 grounding bbox 不一致：
  - 图像中目标可能在右侧（相机视角）
  - grounding bbox 可能标记在左侧（可能是旧帧或坐标映射问题）

(b) Grounding结果与VLM图像的时间差

  GroundingDINO 是异步执行的（ThreadPoolExecutor），返回结果可能延迟 1-2秒。
  收集结果时使用 _collect_finished_request()，得到的是之前的帧的检测结果。
  而 VLM reasoner 看到的是当前帧的图像。
  如果机器人在这段时间内已经转向，grounding 的 bearing 可能已经过时。

  关键日志需要关注：
  - [Grounding] 日志中的 bearing_deg 和 bbox 位置
  - [PrimitiveDecision] 日志中的 action 和 semantic_visible
  - 结果中的 result_age_sec 和 is_current_frame

(c) ReacquireGuard 可能干扰

  如果目标刚从视野中消失，ReacquireGuard 会禁止重复之前的转向方向。
  如果之前执行了 TURN_LEFT，目标消失后，Guard 会禁止 TURN_LEFT，
  即使目标最后一次出现在左边，也可能被迫选择 TURN_RIGHT。

  代码位置：vln_policy.py L1224-1244
  如果 guard.lost_after_visible=True 且 selected == guard.forbidden_action，
  会覆盖为 STOP 或 reacquire_guard_override_action（默认"STOP"）。

(d) Occupancy grid 语义规划器干扰

  如果 semantic_planner_enabled=true，语义规划器可能基于占据栅格计算出一条
  绕过障碍物的路径，该路径可能向右绕行，即使目标在左边。

  代码位置：vln_policy.py L655-735 (_semantic_planner_step)
  语义规划器优先级高于 VLM reasoner，会直接覆盖决策。

### 排查建议

  1. 查看运行日志中的 [PrimitiveDecision] 行，确认 action 来源（LLM_PRIMITIVE / SEMANTIC_LOCAL_PLANNER / REACQUIRE_GUARD）
  2. 对比 [Grounding] 日志中的 bearing_deg 和最终执行的 action
  3. 检查 [ReacquireGuard] 日志是否有 override
  4. 检查 [SemanticPlanner] 日志是否触发了语义路径规划
  5. 如果 grounding bbox 在图像左侧但 VLM 选了右侧候选，
     可能是 VLM 的 prompt 中对 left/right candidate 的描述不够清晰


问题2：阈值不够的目标会有记忆吗？视野消失后为什么朝着更低置信度去了？
----------------------------------------------------------------

### 问题根因

当前实现中，只有 evidence_level="confirmed" 的目标才会写入 LandmarkMap（持久记忆）。

代码位置：landmark_map.py L86-91
```python
has_confirmed_anchor = (
    state.estimated_world_xy is not None
    and bool(state.can_complete)
    and str(state.evidence_level) == "confirmed"
    and bool(map_anchor_allowed)
)
```

对于 potential 级别的目标：
- state.estimated_world_xy 不会更新（只有 confirmed 流水线才会写入）
- state.potential_world_xy 会更新，但 LandmarkMap 不读取它
- 目标离开视野后，LandmarkMap 中没有该目标的条目
- VLM 只能靠 target_memory（历史文本描述）和 last_seen_bearing_hint 来搜索

### 具体流程

1. 目标A（置信度0.75，DINO来源）被检测到
   → evidence_level="confirmed_candidate"（高置信度+DINO+有深度）
   → 但需要3帧一致性才能 confirmed
   → 只看了1-2帧，还没来得及确认

2. 目标A离开视野
   → state.lost_count 增加
   → state.evidence_level 仍为 "confirmed_candidate" 或 "potential"
   → LandmapMap 不创建条目（因为 can_complete=False）

3. 机器人继续搜索，遇到目标B（置信度0.55，也在视野中）
   → 目标B 是另一个物体，被 VLM 误认为目标
   → VLM 选择了朝目标B移动的候选

4. 结果：机器人忘记了之前看到的目标A，转向了更低置信度的目标B

### 核心缺陷

- potential_world_xy 有位置信息，但不参与 LandmarkMap 和导航决策
- VLM reasoner 只能看到当前帧的 grounding 结果 + 文本形式的 target_memory
- 没有"我之前在左边看到过目标"这种几何记忆传给 VLM

### 可能的改进方向

方向A：将 potential 目标也写入 LandmarkMap（标记为 potential）
  - LandmarkMap 新增 potential_entries
  - VLM prompt 中增加 potential target 的位置信息
  - 风险：低置信度目标可能干扰导航

方向B：在 target_memory 中增加几何位置信息
  - 不改 LandmarkMap，而是在 _combined_target_memory_text() 中
    加入 potential_world_xy 和 bearing 信息
  - VLM prompt: "potential target last seen at bearing=left, distance=3.2m"
  - 风险较低，但 VLM 是否能有效利用这些信息不确定

方向C：降低 confirm_min_observations 到 1-2
  - 让高置信度目标更快达到 confirmed 状态
  - 代价：可能增加误确认的风险
  - 当前阈值 confirm_confidence_threshold=0.90 已经很高，
    配合 confirm_min_observations=2 可能是合理的折中

方向D：在 _turn_at_step 和 _maybe_advance_landmark 中增加 potential 搜索逻辑
  - 如果当前没有 confirmed 目标，但有 potential 目标的位置信息，
    可以尝试朝那个方向搜索
  - 这不需要改 LandmarkMap，只需在 policy 层面利用 potential_world_xy

### 建议优先级

1. 先做方向B（最小改动，增加几何记忆文本）
2. 如果效果不够，做方向D（policy层面利用potential位置）
3. 方向C（降低确认帧数）可以同时尝试
4. 方向A（potential写入LandmarkMap）改动最大，最后考虑
